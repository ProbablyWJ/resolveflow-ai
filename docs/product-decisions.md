# 产品决策说明

## 为什么选择这个场景

消费电子售后同时包含用户描述不完整、产品知识、安全风险、业务资格和写操作。它容易被面试官理解，又能要求 Agent 做决策和执行，而不只是生成一段文字。

项目目标不是“AI 客服聊天框”，而是把一个模糊售后诉求推进到安全、可追踪的下一步。

## 为什么需要 Agent

固定 FAQ 或单次模型调用无法稳定判断要核验哪些事实、何时检索手册、何时调用业务工具、步骤失败后如何继续，以及何时必须停止自动处理。因此系统维护结构化任务状态，并根据最新证据决定下一步。

## 人机边界

- 电池或电气高风险信号出现时，立即停止普通排障；
- 不能仅凭模型回答承诺保修、免费换新、赔付或真实业务资格；
- 创建工单属于写操作，必须获得用户明确确认；
- 证据缺失或冲突时继续澄清或转人工，不能编造确定性；
- 演示系统不能对外声称已接入真实企业系统。

## 用户体验原则

用户每轮只看到一个问题组或一个行动。单选、多选和自由填写组件支持渐进式澄清；路由理由、原始实体、工具参数和交接内容只在内部运行详情中展示，不进入客服回复。

## 产品指标

技术指标和用户任务指标分开报告：

- 意图准确率与 Macro-F1；
- 路由、工具、状态的调用链通过率；
- 回复 Judge 各维度；
- 澄清完成率、平均轮次、放弃率、退出点和人工升级率；
- 写操作确认率与重复执行保护。

## 当前边界

当前版本是可在本地完整部署的求职作品。订单、设备、保修、工单和政策均为模拟数据；项目尚未作为生产客服系统验证，也未接入真实 CRM、OMS、物流、支付或人工坐席队列。
